```text

```


```text

```

---

## 2. Batch OSNet inference

The current architecture may extract embeddings one person at a time.

Refactor the ReID extractor so that it supports:

```python
extract_batch(crops)
```

instead of:

```python
extract(crop)
extract(crop)
extract(crop)
...
```

The desired pipeline is:

```text
YOLO-Seg
    ↓
N detections
    ↓
N person crops
    ↓
batch tensor
    ↓
OSNet
    ↓
N embeddings
```

Expected shape:

```text
[N, 3, 256, 128]
        ↓
OSNet
        ↓
[N, embedding_dim]
```

Normalize each embedding after inference.

Maintain backward compatibility with the existing single-image extraction API if other modules use it.

---

## 3. Avoid unnecessary OSNet inference

Do not calculate a Re-ID embedding for detections that are clearly invalid.

Before OSNet:

* confidence gate
* minimum bounding-box size
* valid mask check
* valid crop check
* reasonable aspect-ratio check

Do not extract embeddings from obviously unusable detections.

Add optional configuration parameters such as:

```text
reid_min_detection_confidence
reid_min_width
reid_min_height
reid_min_mask_area
```

Use conservative defaults based on existing V06 behavior.

# PHASE 2 — CROSSING DETECTION + DIRECTION-AWARE ASSOCIATION

The major target is the ID-switch problem when two people cross each other.

Example:

```text
Person A  → → → X ← ← ← Person B
```

At the crossing point, IoU becomes unreliable because both tracks can geometrically overlap.

The tracker must explicitly detect this situation.

---

## 4. Track velocity

For every confirmed track maintain:

```text
previous_center
current_center
velocity_x
velocity_y
speed
direction_vector
```

Use the existing motion model if available.

Do NOT introduce an RNN/LSTM.

The existing motion model should remain the primary short-term predictor.

---

## 5. Direction consistency

For each track and candidate detection calculate a direction-consistency score.

Example:

```text
track direction:
        →

candidate displacement:
        →

high similarity


track direction:
        →

candidate displacement:
        ←

low similarity
```

Use cosine similarity or an equivalent normalized directional metric.

Handle low-speed tracks carefully:

If speed is close to zero:

```text
direction confidence = low
```

and do not strongly penalize direction mismatch.

---

## 6. Predicted position

Use the existing motion prediction to estimate:

```text
predicted_center
```

Then calculate distance between:

```text
predicted_center
```

and:

```text
candidate_detection_center
```

Normalize the distance using the track/detection scale rather than using only raw pixels.

---

## 7. Crossing detector

Add a function similar to:

```python
is_crossing_ambiguous(track_a, track_b, detections)
```

or an equivalent clean design.

Detect a crossing/ambiguity situation when:

1. Two confirmed tracks are spatially close.
2. Their predicted regions overlap or candidate assignments overlap.
3. Both tracks have competing candidate detections.
4. Their boxes/masks have significant overlap.
5. Their trajectories indicate potentially conflicting assignment.

Do not classify every overlap as a crossing.

Avoid false positives for people walking side-by-side.

The crossing detector should produce:

```text
normal
ambiguous
crossing
```

or an equivalent confidence value.

# PHASE 3 — ADAPTIVE ASSOCIATION WEIGHTS

The existing V06 association combines:

* appearance
* motion
* IoU
* gating

Preserve this architecture but make the weights situation-aware.

## Normal condition

Use the existing V06 weighting as the baseline.

Do not unnecessarily change behavior for normal tracking.

## Crossing condition

When crossing/ambiguity is detected:

```text
increase importance of:
    OSNet appearance
    motion consistency
    direction consistency

decrease importance of:
    IoU
```

Do not use arbitrary weights without configuration.

Create configuration parameters such as:

```text
normal_appearance_weight
normal_motion_weight
normal_iou_weight

crossing_appearance_weight
crossing_motion_weight
crossing_iou_weight
crossing_direction_weight
```

Ensure the final score remains normalized.

For example:

```text
association_score =
    appearance_weight * appearance_score
  + motion_weight     * motion_score
  + iou_weight        * iou_score
  + direction_weight  * direction_score
```

The exact default values should be chosen conservatively and documented.

# PHASE 4 — HARD ASSOCIATION GATING

The scoring function alone must not be responsible for preventing ID switches.

Before assignment, reject impossible matches.

Potential gates:

```text
motion distance gate
direction gate
appearance similarity gate
IoU gate
scale/aspect gate
```

Use adaptive gating.

For example:

Normal:

```text
normal gates
```

Crossing:

```text
stricter appearance gate
stricter direction/motion gate
weaker reliance on IoU
```

Do NOT make the gates so strict that normal occlusion recovery becomes impossible.

---

# PHASE 5 — FREEZE RE-ID GALLERY DURING AMBIGUITY/OCCLUSION

This is critical.

The Re-ID gallery must not learn from unreliable observations.

Current problem scenario:

```text
Track A gallery
[A1, A2, A3, A4]

person A crosses person B

bad/mixed crop
      ↓

BAD embedding
      ↓

gallery contamination
```

Prevent this.

## 8. Define embedding reliability

An embedding should be considered reliable only when appropriate conditions are met.

Possible criteria:

* high detection confidence
* sufficient bbox size
* sufficient mask area
* good mask quality
* stable track
* successful association
* no crossing ambiguity
* no severe occlusion
* sufficient OSNet similarity
* stable motion
* identity state allows gallery update

Create a clear function such as:

```python
is_reliable_reid_observation(...)
```

During:

```text
crossing
ambiguous association
heavy occlusion
uncertain identity
```


Existing trusted gallery entries must remain unchanged.

Example:

```text

gallery update = blocked
```

Do not delete existing trusted embeddings simply because a temporary observation is bad.

# PHASE 6 — SOFT MASK EXPERIMENT

The current pipeline uses YOLO-Seg masks before OSNet.

Do not remove this.

Instead implement a configurable mask mode:

```text
hard
soft
bbox
```

### Hard

Existing behavior:

```text
person = 1.0
background = 0.0
```

### Soft

Experiment with:

```text
person = 1.0
background = configurable small value
```

For example:

```text
mask_background_weight = 0.15
```

Conceptually:

```python
soft_mask = background_weight + (
    1.0 - background_weight
) * mask
```

Then:

```python
masked_crop = crop * soft_mask
```

### BBOX

Original RGB crop without segmentation.

This provides an experimental baseline.

# PHASE 9 — PREVENT ID SWITCHES AFTER CROSSING

After a crossing, don't immediately assume the assignment is correct simply because Hungarian matching produced a result.

For an ambiguous crossing:

1. Compare appearance.
2. Compare predicted trajectory.
3. Compare direction.
4. Compare temporal consistency.
5. Check whether the candidate was associated with the same track before crossing.
6. Check whether the proposed assignment would require an implausible trajectory jump.
7. Reject/reconsider the assignment if confidence is insufficient.

If confidence is insufficient:

```text
temporary uncertainty
```

is preferable to:

```text
incorrect identity switch
```

Do not create a new ID unnecessarily if the original track can safely remain alive through short-term occlusion.
