# V06 Tracking Upgrade — Direction-Aware Association & Occlusion Hardening

You are modifying the existing `reid_tracker_v06` repository.

## Primary objective

Improve the current multi-object tracking system to reduce:

* ID switches during person crossing
* ID switches after short occlusions
* Track fragmentation
* False identity claims
* Incorrect identity recovery
* Identity swapping between two nearby/crossing people

**Do NOT introduce RNN, GRU, LSTM, Transformer, or any other neural temporal model.**

The existing Kalman filter, Re-ID system, Track Manager, identity-hardening logic, and metrics architecture must be preserved and improved rather than replaced.

# 3. Add direction-aware association

The existing Track object already maintains velocity/direction information.

Use this information explicitly during association.

For every track calculate a stable recent motion direction.

For example:

```text
vx > 0 → moving right
vx < 0 → moving left
vy > 0 → moving down
vy < 0 → moving up
```

Do not rely on a single-frame velocity.

Use a short history of recent velocity vectors.

The direction estimate should be robust against small detection jitter.

---

# 4. Add direction consistency score

For each:

```text
track ↔ detection
```

calculate a direction-consistency score.

Conceptually:

```text
track_velocity = previous/recent velocity
observed_motion = detection_center - previous_center
```

Use cosine similarity or an equivalent normalized directional comparison.

Example:

```text
Track 7:
velocity → → →

Detection movement:
→ → →

direction_score = high
```

Opposite movement:

```text
Track 7:
velocity → → →

Detection movement:
← ← ←

direction_score = low
```

Handle near-zero velocity carefully.

If the object is stationary or velocity is too small, direction should be considered unreliable rather than automatically penalized.

---

# 5. Add direction to association scoring

The current association should continue using:

* IoU
* motion distance
* scale consistency
* body Re-ID
* face Re-ID
* existing association gates

Add direction consistency as another signal.

Prefer:

```text
association_score =
    existing_score
    + direction_component
```

Do not allow direction to completely override strong Re-ID evidence.

Direction should support identity preservation, not become an absolute rule.

---

# 6. Add direction gating for ambiguous cases

When two or more tracks compete for the same detection, use direction consistency to break ties.

Example:

```text
Track 7  → moving right
Track 12 → moving left

Detection A → right-consistent
Detection B → left-consistent
```

Prefer:

```text
Track 7  → Detection A
Track 12 → Detection B
```

Do this especially when:

* IoU scores are similar
* motion distances are similar
* appearance scores are close
* people are crossing
* bounding boxes overlap heavily

Do NOT apply aggressive direction rejection when Re-ID evidence is strong and unambiguous.

---

# 7. Detect crossing events

Add explicit crossing detection.

A crossing event should be considered when:

* two confirmed tracks become spatially close
* their bounding boxes overlap or nearly overlap
* their predicted positions approach each other
* their velocity vectors indicate opposing/approaching motion

Conceptually:

```text
Track 7  →     ← Track 12

        approaching

             ↓

           overlap

             ↓

          crossing
```

Record the relationship between the tracks.

Use the existing `occluded_by` mechanism where appropriate.

Do not create duplicate tracks simply because two people temporarily overlap.

---

# 8. Protect identities during crossing

When two confirmed identities enter a crossing/occlusion event:

```text
Track 7
Track 12
```

their identity ownership must remain stable.

Do not immediately transfer:

```text
identity 7 → Track 12
identity 12 → Track 7
```

because of a single ambiguous frame.

During crossing:

* preserve the previous identity
* preserve the track ID
* continue Kalman prediction
* preserve trajectory history
* preserve velocity history
* preserve Re-ID gallery
* preserve identity lock state

Only change identity when there is sufficiently strong evidence.

---

# 9. Add association margin protection

For ambiguous association, calculate the difference between the best and second-best candidate.

Example:

```text
Track 7:

Detection A = 0.72
Detection B = 0.70

margin = 0.02
```

This is ambiguous.

Do NOT immediately make a permanent identity change.

Instead:

```text
CANDIDATE
 ↓
observe additional frames
 ↓
stronger evidence
 ↓
CONFIRMED
```

If the margin is high:

```text
Detection A = 0.91
Detection B = 0.42
```

association is much safer.

Use the existing identity-hardening states:

```text
UNKNOWN
CANDIDATE
CONFIRMED
RETAINED
```

rather than creating a second competing identity-state system.

---

# 10. Improve occlusion handling

The repository already has:

```text

OCCLUDED
RECOVERED
LOST
DELETED
```

Do not replace this state machine.

Improve it.

When a confirmed track temporarily loses its detection:

```text
CONFIRMED
   ↓
OCCLUDED
```

During occlusion:

* continue Kalman prediction
* increment occlusion counters
* preserve identity
* preserve appearance gallery
* preserve trajectory
* preserve direction/velocity history

Do NOT immediately create a new identity.

---

# 11. Crossing-specific occlusion

When two tracks overlap:

```text
Track 7 ↔ Track 12
```

treat this as a special occlusion/crossing situation.

Maintain:

```text
track.crossing_partner
track.crossing_start_frame
track.crossing_frames
```

or an equivalent structure consistent with the existing design.

When the people separate, attempt recovery using:

1. Kalman predicted position
2. motion consistency
3. direction consistency
4. IoU
5. body Re-ID
6. face Re-ID when available
7. historical trajectory

The goal is:

```text
Before crossing:

Person A → ID 7
Person B → ID 12

After crossing:

Person A → ID 7
Person B → ID 12
```

---

# 12. Do not overtrust Re-ID

Re-ID should remain one component of association.

Do not implement:

```text
highest Re-ID similarity = automatic identity
```

Instead combine:

```text
motion
+
IoU
+
direction
+
appearance
+
temporal consistency
```

Strong face evidence may remain a special high-confidence case according to the existing identity-hardening design.

Body-only evidence should continue to respect the existing candidate/confirmation logic.

---

# 13. Preserve identity ownership

The existing identity ownership/locking mechanism must remain.

A confirmed identity should not simultaneously belong to multiple active tracks.

Example:

```text
Identity A → Track 7
```

must not become:

```text
Identity A → Track 7
Identity A → Track 12
```

unless the existing system explicitly supports a safe transition.

During crossing, prefer retaining the original owner.

# 14. Improve recovery logic

When a detection reappears after occlusion, recovery should consider:

```text

distance from prediction
direction consistency
trajectory consistency
body appearance
face appearance
gallery similarity
```

Recovery should be more permissive than normal association where appropriate, but should still prevent obvious identity swaps.

Do not simply increase every threshold.

Use the existing distinction between normal association and recovery.

# 17. Keep performance in mind

The previous system experienced severe FPS limitations.

Therefore:

* Do not add expensive neural networks.
* Do not add RNN/GRU/LSTM.
* Do not perform unnecessary Re-ID extraction.
* Do not compare every detection against every historical embedding if the existing gating can reduce candidates.
* Reuse existing embeddings and histories.
* Keep direction calculations lightweight.
* Prefer vectorized/simple numerical operations.

The new direction/crossing logic should have minimal computational overhead compared with YOLO/Re-ID inference.
